# stock-report: rules for coding agents

## Goal
On a WeChat keyword (股票报告 / 股票简报 / stock report / stock brief), reply within 30 s with exactly two messages: a text summary and a PDF report. Per market (US, HK, CN): three ratings, each a list of top candidates, as a sell-side analyst rates stocks without anyone's portfolio: 20 Buy (买入, expected to go up: the buy portfolio, chosen from the whole liquid market, equal amounts), 10 Hold (持有, expected to be stable) and 10 Sell (卖出, expected to go down), and what to expect from each rating's history. Each card shows the price, the value, quality, growth and momentum grades, why the name is there, the key risk, the cost of one board lot, the review's finding, an AI note and a re-check date. The aim is moderate: beat the index fund over the year you hold the names, at about the market's level of risk.
On any other message (stages 9-12, docs/PLAN.md "Single-stock research"), a router reads it: the exact keywords and an exact code or full name without AI, DeepSeek for the rest, and a short question when the text is unclear. For a company listed in CN, the US or HK the reply is a sell-side research report in three messages: an acknowledgement, a text summary and a PDF with a rating (买入 / 持有 / 卖出, or 不评级), a 12-month target price, the investment thesis, the bull and bear cases, a 3-year forecast, the valuation behind the target (a method per type of company), catalysts, risks, the accounts' quality, and a comparison with the daily screening's rating that explains a large difference. One company per message.

## Read first
docs/PLAN.md has the method, the stages and the current status. The earlier plans (v1-v3 with Phases 1-13, and the 2026-10-22 plan) are in docs/archive/ as reference only, not as paths to follow. Do only the stage you were asked to do.

## Layout
stockreport/fetch/ (one module per data source) → universe.py → signals.py (the value, quality, growth and momentum components, percentiles, the distress probability) → score.py (families, score, grades, card lines) → lists.py (Buy, Hold, Sell) → report.py + render/ (HTML → PDF, text summary) → deliver.py; plus listener.py, track.py and history.py (the multi-year tables).
crosscheck.py compares each market's key figures with a second source and raises day-over-day drift alarms. The filing rules (events.py: each filing's kind, routine ones dropped), the periodic-report passages (passages.py: code cuts the hard-flag passages of each listed name's latest report, fetch/filings.py) and your verdicts (verdicts.py: vetoes and confirms) feed the results review. backtest/ (outside the app) holds the backtest harness and data builders; docs/BACKTEST.md has its results and commands.
review.py is the results review on request, the project's one DeepSeek step (sources gathered by the build: fetch/filings.recent, fetch/news.py and passages.py; one call per name screens with quoted findings, quotes.py checks them, and comments: the AI note and the company line, notes.py); report.fresh() runs it before the keyword reply and `send`.
Everything runs without Claude Code: launchd runs the 06:30 `run` and the listener with the project's own Python, and no step calls an AI except DeepSeek in three places (the router, the results review, the research report's words); without DeepSeek the screening report still goes out, marked 审核暂不可用, and a research report goes out with its numbers and its AI sections marked 暂不可用. Your installed Claude skills are ported into the program (their data and calculations as code, their questions as DeepSeek prompts stored in the project), never called at runtime.
stockreport/research/ (stages 9-12) holds the single-stock research: per-stock data and the fact sheet, the valuation and rating, DeepSeek's writing, the comparison with the screening, and the router listener.py hands messages to.
bridge/wechat.mjs is the WeChat helper (Node). data/ is the daily cache and reports/ the outputs; both are git-ignored.

## Rules
1. Free data only. Follow the Storage section in docs/PLAN.md: raw responses are temporary, only small extracted tables are kept, and cleanup runs after every build. data/ + reports/ must stay under 2 GB.
2. All numbers come from code + data. The LLM never writes a forecast, price, fair value, target, rating or score, and never extracts a number for a calculation. DeepSeek is used in three places: (a) reading your WeChat message: the intent and company hints, which code confirms against the official listings; (b) the results review: it reads the card and the sources code gives it (filing titles, periodic-report passages, headlines), flags findings that each quote a source (code checks the quote, and a hard red flag swaps a pick for the next one), and writes a short note and a one-line company description in words only; (c) the research report's words: business, thesis, bull and bear cases, outlook, risks and the comparison with the screening, from the fact sheet and sources code gives it. In (c) a figure in its prose is a fact-sheet key code fills in, and any other figure is rejected unless it appears in the source line it cites; the company's own words may be quoted, checked verbatim, and never feed a calculation.
3. Rank every stock with one rule-based score per market: the value, quality, growth and momentum families defined in docs/PLAN.md, equal weights, each market's ingredients taken from published research on that market and never tuned to our backtest. No hand-typed per-company assumptions. Per-company research only through the results review (with its periodic-report passages, read for the listed names, cached per filing) and user verdicts (veto or confirm with an expiry, never numbers). a-stock-data is fine as an endpoint reference. Research reports value one company with code-fixed inputs (the consensus, its own history, Damodaran's published data, the type rules in docs/PLAN.md); no hand-typed per-company assumptions there either.
4. Lists are rank-based and always shown, per market: 20 Buy from the whole scored market (each sector's places by its share of the market's free-float value, filled by its best scores, equal amounts), 10 Hold and 10 Sell (at most 2 per sector), as docs/PLAN.md's "Lists" says. No portfolio enters the lists: no holdings check. How you split your money between the list, funds and bonds is yours: the report never advises it. A market whose build fails shows its last good lists with their date. Never fail the whole report.
5. Missing or inconsistent data: drop the stock and take the next one. Never invent data or hard-code tickers into the picks.
6. Keep it small: no frameworks, "gates", "contracts", ledgers, hashes, attestations or handoff documents. Target under 9,500 lines of app Python (stockreport/; 6,000 before the research module), with files under 400 lines. Ask before adding a dependency.
7. Tests: pytest for the scoring and valuation math and the parsers (using small saved samples), plus one end-to-end dry run. Nothing more.
8. One stage per session. Before reporting a stage done, run the stage-reviewer agent (.claude/agents/stage-reviewer.md) with fresh context and include its answers; it runs on Sonnet (its `model:` line, to save tokens), so don't override its model when calling it. When the stage's "done when" is met, update the status in docs/PLAN.md, commit, then stop and report in 10 lines or fewer.
9. Ask me before: sending any WeChat message, creating or pushing to GitHub repos, installing launchd jobs, or adding any paid service.
10. Never print, log or commit secrets from .env.
11. If something is ambiguous or a stage can't be done as written, stop and ask. Don't build workarounds. Investment-method choices are the agent's to make from published evidence, with the reason written in docs/PLAN.md: don't hand the user choices they can't judge, and don't call something the user's goal unless they said it.
12. Usefulness first: a change is worth doing only if it changes what is bought, held or avoided, what a research report rates or says, or what the report says to expect, or fixes a fault. The method changes only to fix a bug or to follow new published evidence, never because a backtest number or one name looked wrong. No pass/fail gates on shipping and no test whose result would change nothing. Don't do work whose only effect is that results look more plausible or better explained (normalizing medians, outlier labels, plausibility targets).
13. Releases: end every commit message with a trailer line `Release: major|minor|patch|none`, judged by materiality as README "Versions and releases" defines (major: the method or the ratings' meaning changes; minor: a stage or a change to what is bought, held, sold or what the report says to expect; patch: a fix that keeps the method; none: docs, tests, backtest/). On push to main, .github/workflows/release.yml tags the version and writes the release notes; never tag or release by hand.

## Commands
uv run python -m stockreport fetch --market cn|us|hk
uv run python -m stockreport run [--market cn|us|hk]                # fetch + score + lists + review sources + PDF (no DeepSeek)
uv run python -m stockreport review                                 # results review (DeepSeek), then the PDF
uv run python -m stockreport send [--test]                          # text summary + PDF to WeChat (reviewed first)
uv run python -m stockreport listen                                 # listener (launchd): keywords now, the router from stage 12
uv run python -m stockreport research CODE --facts                  # single-stock fact sheet (stage 9); the report PDF comes in stage 11
uv run python -m stockreport track                                  # performance scorecard
uv run python -m stockreport verdict [CODE veto|confirm --until D --reason "..."]  # your verdicts (no args: list)
uv run python -m stockreport cleanup [--dry-run]                    # apply storage retention
uv run pytest
